# Ikrom Shashlik — сайт шашлычной

Фронтенд сайта шашлычной: главная страница, меню с категориями и поиском, корзина и оформление заказа. Интерфейс на русском и узбекском, цены в сумах.

Стек: Vite, React 19, React Router, Framer Motion, Lucide, CSS Modules. Шрифты Sofia Sans и Sofia Sans Extra Condensed подключены локально через Fontsource (кириллица и узбекская латиница).

> Все данные демонстрационные: адрес, телефон, ссылки, цены, состав блюд и фотографии. Перед запуском замените их на настоящие (см. «Что где редактировать»).

## Запуск

Нужен Node.js 20 или новее.

```bash
cd frontend
npm install
cp .env.example .env    # по желанию, см. «Приём заказов»
npm run dev             # http://localhost:5173
```

| Команда           | Что делает                                   |
| ----------------- | -------------------------------------------- |
| `npm run dev`     | dev-сервер с горячей перезагрузкой           |
| `npm run build`   | production-сборка в `frontend/dist`          |
| `npm run preview` | локальный просмотр собранной версии          |
| `npm run lint`    | ESLint                                       |
| `npm test`        | unit-тесты (Vitest): цены, корзина, валидация, телефон, поиск, часы работы, отправка заказа |

## Что где редактировать

| Что                                                    | Файл                                         |
| ------------------------------------------------------ | -------------------------------------------- |
| Адрес, телефон, часы работы, соцсети, точка на карте   | `frontend/src/config/site.js`                |
| Стоимость доставки, бесплатная доставка, минимальный заказ | `frontend/src/config/site.js` → `delivery` |
| Категории, блюда, цены, вес, описания, наличие, «популярное» | `frontend/src/data/menu.js`            |
| Тексты интерфейса (RU / UZ)                            | `frontend/src/i18n/translations/ru.js`, `uz.js` |
| Логотип и иконка вкладки (вырезаны из `logo ikrom shashlik.jpg`) | `frontend/public/images/brand/`       |
| Фото блюд                                              | `frontend/public/images/dishes/<image>-520.webp` и `-900.webp` |
| Фото для hero, «О нас», «Почему мы»                    | `frontend/public/images/site/`               |
| Список источников фото                                 | `frontend/src/data/photoCredits.js` (страница `/credits`) |

Когда данные станут настоящими, поставьте `isDemo: false` в `site.js`, и пометка о демо-данных в блоке «Контакты» исчезнет.

Ссылки на Telegram, Instagram и телефон с пустым `href` выводятся обычным текстом, без ссылки. Укажите `href`, и они станут кликабельными.

Блюдо с `available: false` остаётся в меню с пометкой «Временно нет», но в корзину его не добавить. Если оно уже лежит в корзине, оформить заказ не получится, пока его не уберут.

## Как устроено

- **Меню** берётся из `src/data/menu.js`. Категории переключаются без перезагрузки. Поиск ищет по названиям на обоих языках и не различает «ё/е» и узбекские апострофы (`oʻ`, `o'`). Есть сортировка по популярности, цене и названию.
- **Корзина** хранится в `localStorage`: переживает перезагрузку и синхронизируется между вкладками. Названия и цены всегда берутся из актуального меню.
- **Оформление** (`/checkout`): доставка или самовывоз, имя, телефон в формате `+998 XX XXX-XX-XX`, адрес (только для доставки), комментарий до 500 символов. Ошибки показываются у полей, фокус переходит на первое неверное. Учитываются минимальная сумма доставки и недоступные блюда.
- **Корзина очищается только после того, как сервер подтвердил заказ.** При любой ошибке она сохраняется.
- Доступность: навигация с клавиатуры, ссылка «Перейти к содержимому», фокус-ловушка в корзине и мобильном меню, закрытие по Esc, подписи у всех полей, учёт `prefers-reduced-motion`.

## Приём заказов

Это только фронтенд, без сервера. Принимать заказы и отправлять их в Telegram он не может сам по себе, поэтому:

- **`VITE_ORDER_API_URL` не задан** (по умолчанию). При отправке появляется сообщение «Онлайн-заказ пока не подключён», корзина остаётся на месте. Покупатель может скопировать текст заказа и отправить его в Telegram или позвонить, если в `site.js` указаны ссылки. Успешная отправка **не имитируется**.
- **`VITE_ORDER_API_URL` задан.** Заказ уходит `POST`-запросом на этот адрес.

### Формат запроса

```http
POST {VITE_ORDER_API_URL}
Content-Type: application/json
```

```json
{
  "items": [{ "id": "plov", "quantity": 2 }],
  "customer": { "name": "Азиз", "phone": "+998901234567" },
  "fulfillment": "delivery",
  "address": "ул. Навои, 12, кв. 5",
  "comment": "без лука",
  "language": "ru",
  "clientTotals": { "subtotal": 84000, "deliveryFee": 15000, "total": 99000 }
}
```

`fulfillment` принимает значения `"delivery"` или `"pickup"`. При самовывозе `address` пустой.

### Ожидаемые ответы

| Ответ сервера                         | Что видит покупатель                                          |
| ------------------------------------- | ------------------------------------------------------------- |
| `2xx` + `{ "number": "IK-1042" }`     | «Заказ принят», номер заказа. Корзина очищается               |
| `2xx` без тела                        | «Заказ принят» без номера                                     |
| `4xx` + `{ "detail": "..." }` или `{ "message": "..." }` | «Заказ не принят» и текст причины от сервера |
| `5xx`, нет сети, нет ответа за 15 с   | «Не удалось отправить заказ», кнопка «Отправить ещё раз»      |

### Что обязательно сделать на сервере

1. **Пересчитать сумму заказа.** `clientTotals` передаются только для справки. Цены берите из своей базы по `items[].id`.
2. Проверить наличие блюд, количество (на сайте от 1 до 50 порций одного блюда), телефон и адрес.
3. **Токен Telegram-бота хранить только на сервере**, в переменных окружения. Всё, что начинается с `VITE_`, попадает в публичный JavaScript, поэтому секреты туда класть нельзя.
4. Если сайт и API на разных доменах, включить CORS для домена сайта.

### Админ-панель

В этом фронтенде её нет. Защищённая панель (просмотр заказов, смена статусов, управление меню) требует сервера с настоящей авторизацией. Скрытая страница на фронтенде не защищает данные. Панель стоит делать вместе с бэкендом, например на Django admin или DRF с сессионной авторизацией.

## Деплой

`npm run build` собирает статический сайт в `frontend/dist`. Его можно выложить на любой статический хостинг: Nginx, Netlify, Vercel, Cloudflare Pages.

Сайт использует клиентский роутинг (`/checkout`, `/credits`), поэтому все неизвестные пути должны отдавать `index.html`. Пример для Nginx:

```nginx
location / {
  try_files $uri /index.html;
}
```

## Фотографии

Фото временные, из открытых источников: Pexels (Pexels License) и Wikimedia Commons (CC0 и CC BY-SA 3.0). Все изображения обрезаны, уменьшены и переведены в WebP (от 15 до 160 КБ на файл). Список авторов и лицензий есть на странице `/credits` и в `src/data/photoCredits.js`. Когда замените фото своими, удалите соответствующие записи.

## Структура

```
frontend/
  public/images/        фото (WebP, два размера для srcset)
  src/
    config/site.js      контакты, часы, доставка
    data/               меню и источники фото
    i18n/               переводы RU / UZ и переключатель языка
    context/            корзина и уведомления
    lib/                форматирование, телефон, корзина, валидация, поиск, часы работы
    services/           отправка заказа
    components/         layout, home, menu, cart, checkout, ui
    pages/              главная, оформление, источники фото, 404
    styles/             токены и базовые стили
```
